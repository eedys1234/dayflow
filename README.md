# Dayflow

Rust + Tauri v2 기반 일정/할 일 관리 데스크탑 앱.

- 기능 설계: [FEATURES.md](FEATURES.md)
- 배포 및 자동 업데이트 설계: [RELEASE.md](RELEASE.md)

**상단 앱바** — 브랜드 · `+ 새 할 일` · `지남 N`(누르면 지난 항목 드로어) · `오늘 N` ·
테마 토글 · 버전 배지. 버전은 `tauri.conf.json` 값을 읽으므로 곧 그 빌드가 나온 태그입니다.

**좌측 아이콘 레일** — Tasks / Calendar / Settings.

할 일 카드를 누르면 상세 모달이 열립니다. 캘린더의 빈 시간대를 누르면 그 시각이
채워진 채로 새 할 일 모달이 열립니다.

**뷰 전환**

| 뷰 | 내용 |
|---|---|
| 일 · 보드 | **대기 / 진행 중 / 완료** 세 열. 카드를 끌어다 놓으면 상태가 바뀝니다 |
| 일 · 타임라인 | 하루를 24시간 시간축으로. 현재 시각 표시선 포함 |
| 주 | 7일 × 24시간. 같은 시간대에 몰린 카드는 좌우로 나뉩니다 |
| 월 | 6주 그리드. 칸당 3건까지 보이고 넘치면 `+N개 더` |

주/월 뷰에서 카드를 다른 시간·날짜로 끌어다 놓으면 예정 시각이 옮겨지고,
알림도 새 시각 기준으로 다시 예약됩니다.

**단축키** — `1`/`2`/`3` 화면 전환 · `N` 새 할 일 · `Esc` 닫기 ·
캘린더에서 `T` 오늘, `←/→` 이전·다음, `D`/`W`/`M` 뷰 전환

## Excel 내보내기

캘린더 툴바의 `⭳ Excel` 은 **현재 보이는 기간**을, 설정 → 데이터 탭의 `전체 내보내기` 는
기한 없는 항목까지 **전부** 내보냅니다.

| 시트 | 내용 |
|---|---|
| 일정 | 날짜 · 요일 · 시작 · 종료 · 소요(분) · 제목 · 상태 · 우선순위 · 알림 · 반복 알림 · 메모 |
| 요약 | 기간 · 전체/대기/진행 중/완료/지남 건수 · 완료율 |

머리글 고정과 자동 필터가 걸려 있고, 날짜·시각은 문자열이 아니라 **Excel 날짜 값**이라
정렬과 계산이 그대로 됩니다. 지난 항목은 붉게, 완료 항목은 회색으로 표시됩니다.

## 실행

```bash
npm install
```

개발 모드 (프론트 핫리로드 + Rust 자동 재빌드):

```bash
npm run app
```

설치 파일 빌드:

```bash
npm run app:build
```

## 알림 동작 방식

```
할 일 등록 (알림 체크 + "10분 전")
        │  remind_at = due_at - 10*60  으로 저장
        ▼
scheduler.rs ── 20초마다 ──► remind_at <= now 이고 notified_at 이 비어 있는 항목 조회
        ▼
notify.rs ──► 알림 창 생성(없으면) → 우측 하단으로 이동 → 카드 전달
        ▼
notification.tsx ──► 카드 표시. 완료 / 10분 후 / 1시간 후 / 닫기
```

**설계상 알아둘 점**

- 알림 창은 별도의 투명 `WebviewWindow` 입니다. OS 기본 알림이 아니라 위치와 모양을 직접 제어합니다.
- 카드가 모두 사라지면 창을 **숨기기만** 합니다. 파괴하지 않는 이유는 다음 알림에서 webview를 다시 만드는 비용을 피하기 위해서입니다.
- 창 높이는 카드 개수에 맞춰 실시간으로 조절됩니다. 투명 영역도 클릭을 가로채기 때문에, 남는 공간이 있으면 뒤쪽 창을 못 누르게 됩니다.
- 앱이 꺼져 있는 동안 지난 알림은 다시 켰을 때 표시됩니다. 단 24시간이 넘은 것은 조용히 발송 처리만 합니다.
- 시각은 모두 Unix epoch 초(UTC)로 저장하고, 표시할 때만 로컬 시간으로 변환합니다.

## 테마

`라이트 / 다크 / 시스템` 세 가지이며 앱바의 아이콘 또는 설정 → 화면 탭에서 전환합니다.
선택값은 SQLite `settings` 테이블에 저장되고, Rust가 모든 창에 이벤트를 던져
**알림 창까지 같은 테마를 따라갑니다.** `localStorage` 를 쓰지 않은 이유가 이것입니다 —
메인 창과 알림 창은 서로 다른 `WebviewWindow` 라 공통 전파 채널이 필요합니다.

## 데이터 위치

| OS | 경로 |
|---|---|
| Windows | `%APPDATA%\com.colosseum.dayflow\schedule.db` |
| macOS | `~/Library/Application Support/com.colosseum.dayflow/schedule.db` |
| Linux | `~/.local/share/com.colosseum.dayflow/schedule.db` |

> `identifier`(`com.colosseum.dayflow`)는 이 경로에 그대로 들어갑니다.
> 배포 이후에 바꾸면 기존 사용자의 데이터가 사라진 것처럼 보이므로,
> 첫 릴리스 전에 확정해야 합니다.

## 백업과 복원

설정 → 데이터 탭에서 다룹니다.

- **자동 백업** — 하루 1회, 보관 개수(5·10·20·30)를 넘으면 오래된 것부터 정리
- **지금 백업** — 스냅샷을 하나 더 생성
- **복원** — 목록에서 고르면 **다음 시작 때** 적용됩니다

복원을 즉시 하지 않는 이유가 있습니다. 앱이 DB 파일을 쥔 채로 바꿔치기하면 WAL에 남은
옛 내용이 되살아나 데이터가 섞입니다. 그래서 복원 파일을 `schedule.db.restore-pending`
으로 예약해 두고, 다음 시작 시 DB를 열기 **전에** WAL/SHM까지 지우고 교체합니다.
덮어쓰기 직전의 원본도 자동으로 한 부 남깁니다.

백업은 파일 복사가 아니라 **SQLite 온라인 백업 API**를 씁니다. 복사는 쓰기 도중이면
깨진 스냅샷이 나올 수 있습니다. 복원 전에는 SQLite 헤더를 확인해 엉뚱한 파일을
얹지 못하게 막습니다.

## 빠른 입력

전역 단축키를 누르면 화면 가운데 위에 입력창이 뜹니다. 한 줄로 시각까지 적을 수 있습니다.

| 입력 | 결과 |
|---|---|
| `팀 회의 15:00` | 오늘 15:00 |
| `보고서 내일 9:30` | 내일 09:30 |
| `점심 약속 오후 12시` | 오늘 12:00 |
| `문서 정리` | 기한 없음 |

시각이 인식되면 10분 전 알림도 함께 걸립니다.

> **단축키 충돌** — 한국어 Windows 에서는 IME 가 `Ctrl+Shift+Space` 나
> `Ctrl+Alt+Space` 를 이미 쓰고 있는 경우가 많습니다. 등록에 실패하면 대안을
> 차례로 시도하고, **실제로 걸린 조합**을 설정 화면에 표시합니다.
> 조용히 실패하면 사용자는 단축키가 왜 안 먹는지 알 수 없기 때문입니다.
