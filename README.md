# Dayflow

Rust + Tauri v2 기반 일정/할 일 관리 데스크탑 앱.

- 기능 설계: [FEATURES.md](FEATURES.md)
- 배포 및 자동 업데이트 설계: [RELEASE.md](RELEASE.md)

## 현재 구현 상태

| 기능 | 상태 |
|---|---|
| 할 일 등록 / 수정 / 삭제 (+ 실행 취소) | ✅ |
| 대기 / 진행 중 / 완료 3단계 상태 | ✅ |

| **주별 뷰** — 7일 × 24시간 시간축, 드래그로 일정 이동 | ✅ |

**LNB(좌측)** — 할 일 등록·수정 폼이 항상 떠 있습니다. 캘린더에서 카드를 누르면 이 폼이
수정 모드로 바뀌고, 빈 시간대를 누르면 예정 시각이 자동으로 채워집니다.
예정 시각이 없어 캘린더에 올라갈 수 없는 항목은 아래 "기한 없음" 목록에 모입니다.

**뷰 전환**

| 뷰 | 내용 |
|---|---|
| 일 · 보드 | **대기 / 진행 중 / 완료** 세 열. 카드를 끌어다 놓으면 상태가 바뀝니다 |
| 일 · 타임라인 | 하루를 24시간 시간축으로. 현재 시각 표시선 포함 |
| 주 | 7일 × 24시간. 같은 시간대에 몰린 카드는 좌우로 나뉩니다 |
| 월 | 6주 그리드. 칸당 3건까지 보이고 넘치면 `+N개 더` |

주/월 뷰에서 카드를 다른 시간·날짜로 끌어다 놓으면 예정 시각이 옮겨지고,
알림도 새 시각 기준으로 다시 예약됩니다.

**단축키** — `T` 오늘 · `←/→` 이전·다음 · `D`/`W`/`M` 뷰 전환

## 실행

```bash
npm install
```

개발 모드 (프론트 핫리로드 + Rust 자동 재빌드):

```bash
npm run app
```

설치 파일 빌드:

```bash
npm run app:build
```

첫 실행은 Rust 의존성 약 490개를 컴파일하므로 5~15분 걸립니다. 이후에는 증분 빌드입니다.

## 알림 동작 방식

```
할 일 등록 (알림 체크 + "10분 전")
        │  remind_at = due_at - 10*60  으로 저장
        ▼
scheduler.rs ── 20초마다 ──► remind_at <= now 이고 notified_at 이 비어 있는 항목 조회
        ▼
notify.rs ──► 알림 창 생성(없으면) → 우측 하단으로 이동 → 카드 전달
        ▼
notification.tsx ──► 카드 표시. 완료 / 10분 후 / 1시간 후 / 닫기
```

**설계상 알아둘 점**

- 알림 창은 별도의 투명 `WebviewWindow` 입니다. OS 기본 알림이 아니라 위치와 모양을 직접 제어합니다.
- 카드가 모두 사라지면 창을 **숨기기만** 합니다. 파괴하지 않는 이유는 다음 알림에서 webview를 다시 만드는 비용을 피하기 위해서입니다.
- 창 높이는 카드 개수에 맞춰 실시간으로 조절됩니다. 투명 영역도 클릭을 가로채기 때문에, 남는 공간이 있으면 뒤쪽 창을 못 누르게 됩니다.
- 앱이 꺼져 있는 동안 지난 알림은 다시 켰을 때 표시됩니다. 단 24시간이 넘은 것은 조용히 발송 처리만 합니다.
- 시각은 모두 Unix epoch 초(UTC)로 저장하고, 표시할 때만 로컬 시간으로 변환합니다.

## 테마

`라이트 / 다크 / 시스템` 세 가지이며 LNB 하단에서 전환합니다.
선택값은 SQLite `settings` 테이블에 저장되고, Rust가 모든 창에 이벤트를 던져
**알림 창까지 같은 테마를 따라갑니다.** `localStorage` 를 쓰지 않은 이유가 이것입니다 —
메인 창과 알림 창은 서로 다른 `WebviewWindow` 라 공통 전파 채널이 필요합니다.

|---|---|
| Windows | `%APPDATA%\com.colosseum.dayflow\schedule.db` |

| Linux | `~/.local/share/com.colosseum.dayflow/schedule.db` |

> `identifier`(`com.colosseum.dayflow`)는 이 경로에 그대로 들어갑니다.
> 배포 이후에 바꾸면 기존 사용자의 데이터가 사라진 것처럼 보이므로,
> 첫 릴리스 전에 확정해야 합니다.
